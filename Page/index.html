Payment webhook

When a payment comes in, the payment gateway calls your app with a webhook. Gateways resend the same webhook when they do not get the answer in time, so the same payment can arrive two or three times. This app starts a skail run for each webhook, with the run id derived from the event id: the resends land on the same run, and the order is released once. A payment that does not match its invoice goes to finance instead.

You play the gateway:

  1. In a scenario, click Send payment.
  2. Click Resend the same webhook as many times as you like.
  3. See that the webhooks pile up, but there is still one run and the order is released (or reviewed) once.
